读书笔记---Effective Modern C++(三)：条款8 优先用 nullptr

条款8：优先用 nullptr，而不是 0 和 NULL

0 和 NULL 本质上是整数，只是在“只能放指针”的上下文里被勉强当成空指针；nullptr 才是真正的空指针字面量。

1. 0 和 NULL 都不是指针

字面量 0 的类型是 int。只有在必须使用指针的上下文里，编译器才会退一步把它解释为空指针。

NULL 也类似，只是它的具体类型由实现决定，可能是 int，也可能是 long 之类的整数类型。重点不是它到底是哪种整数，而是它不是指针类型。

这会导致重载决议的意外：

f(NULL) 的行为不确定，是因为实现可能把 NULL 定义成 0L。这时 long -> int、long -> bool、0L -> void* 的转换程度相近，调用可能产生歧义。

2. nullptr 的类型

nullptr 的类型是 std::nullptr_t。这个类型可以隐式转换成所有原始指针类型，所以 nullptr 看起来像“任意类型的指针”。

这既避免了重载决议的意外，也让代码意图更清楚。

5. 顺带的建议

书里还重申了一条 C++98 就有的建议：避免对整数类型和指针类型做重载。即使有了 nullptr，这种重载仍然容易让人踩坑；老代码里可能还在用 0/NULL，你无法保证所有调用方都改了。

6. 记住

  • 表示空指针时，优先用 nullptr，不要用 0 或 NULL。
  • nullptr 的类型是 std::nullptr_t，可以隐式转换成所有原始指针类型。
  • 模板推导会把 0 推成 int、把 NULL 推成某种整数类型；只有 nullptr 能保持“空指针”的语义。
  • 尽量避免对整数类型和指针类型做重载。
