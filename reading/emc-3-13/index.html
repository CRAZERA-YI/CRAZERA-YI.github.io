条款13：优先用 const_iterator，而不是 iterator

只读遍历就用 const_iterator。C++98 里它又难创建又难使用，C++11 的 cbegin/cend 才让这件事真正实用。

1. 为什么用 const_iterator

const_iterator 相当于“指向 const 的指针”：可以读，不能通过它修改元素。这符合“能用 const 就用 const”的原则。

问题一堆：

  • 非 const 容器没有简单办法直接得到 const_iterator，只能强转。
  • insert/erase 在 C++98 里只接受 iterator，不接受 const_iterator。
  • const_iterator 不能可移植地转换成 iterator，static_cast 不行，reinterpret_cast 也不行。

所以 C++98 里 const_iterator 常常“理论上更好，实际上不值得”。

5. 记住

  • 只读遍历优先用 const_iterator。
  • C++11 的 cbegin/cend 让 const_iterator 容易获得，insert/erase 也接受它。
  • 写最大化泛型代码时，优先用非成员的 begin/end/cbegin/cend，不要假设成员函数一定存在。
  • C++11 缺少非成员的 cbegin/cend，C++14 补上了；C++11 可以自己实现一个。
