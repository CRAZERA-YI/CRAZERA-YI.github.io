2. 情形一：花括号初始化器（Braced Initializers）

假设 f 接收 const std::vector<int>&：

为什么失败？直接调 f 时，编译器看得见形参类型 std::vector<int>，知道要把 {1, 2, 3} 转成什么；但调 fwd 时，形参是未推导的模板参数 Ts&&，而标准规定向未声明为 std::initializer_list 的函数模板参数传花括号属于非推导语境（non-deduced context），编译器拒绝推导。出现这种情况的原因呢,大概是哈,对于一个函数模板,他不是在编译器生成的,他是在实例化对象的时候才有的,此时Ts根本没推导出来,所以这就会导致里面的f不知道Ts是个啥玩意,所以报错

3. 情形二：用 0 或 NULL 表示空指针

把 0 或 NULL 传给模板时，类型推导会把它们推导成整型（通常是 int），而不是指针类型。转发给需要指针的 f 时就会出错。所以说不是必然出错,取决于f的参数类型

解决办法：永远用 nullptr 代替 0 和 NULL。反正也确实是这样的,现代C++不可能还有人用NULL了

4. 情形三：仅有声明的整型 static const / constexpr 数据成员

在类内声明整型的 static const 或 static constexpr 成员时，通常不需要在 .cpp 里再给定义，因为编译器会直接做常量传播（把用到它的地方直接替换成字面值，不分配内存）：

为什么链接会失败？因为 fwd 的形参是万能引用，而引用在底层通常按指针实现，绑定引用就等于取地址。一旦要取 Widget::MinVals 的地址，它就必须有实际分配的内存，光靠类内声明就不够了。都不是当作变量处理的(字面量)哪里来的地址,所以就很尴尬了

6. 情形五：位域（Bitfields）

位域 其实就是一个可以自定义成员元素长度的类,所以你可以定义一个31位的int,但是有个问题就是,位域里面的成员是没有单独的地址的,因为它不能像普通成员一样对其,没法用地址表示

为什么失败？因为 h.totalLength 是个位域（可能跨越不是字节对齐的比特位），C++ 标准明确规定：非 const 引用不能绑定到位域（因为无法直接用普通指针指向任意比特位；而绑定到 const 引用时，编译器其实是拷贝了一份临时整型再把引用绑到临时对象上）。

fwd 的形参是万能引用，h.totalLength 是非 const 左值，试图直接绑定非 const 左值引用到位域，违反标准而报错。

7. 记住

  • 当模板类型推导失败或推导出错误类型时，完美转发就会失败。
  • 会导致完美转发失败的实参种类包括：花括号初始化器、作为空指针的 0 或 NULL、仅有声明的整型 static const 及 constexpr 数据成员、模板及重载函数名，以及位域。
