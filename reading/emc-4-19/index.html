读书笔记---Effective Modern C++(四)：条款19 优先用 shared_ptr

条款19：用 std::shared_ptr 管理共享所有权资源

std::shared_ptr 通过引用计数实现共享所有权，最后一个 shared_ptr 销毁对象。它很方便，但比 unique_ptr 大、慢，而且控制块用错(this指针问题)会导致重复销毁。

1. 共享所有权和引用计数

一个对象可以被多个 shared_ptr 共同拥有，没有哪一个“单独拥有”它。每个 shared_ptr 都指向同一个控制块，控制块里记录有多少个 shared_ptr 指向该对象。

  • 拷贝 shared_ptr：引用计数加一。
  • 销毁 shared_ptr：引用计数减一。
    咋叫销毁呢,比如传入一个函数,传入一个容器,然后函数返回,或者从容器里面把拷贝构造的对象给pop都算
  • 拷贝赋值：先减左边的旧对象，再加右边的新对象。

销毁时机是确定的，像析构函数，不像垃圾回收那样不确定；但调用方不需要手动管理生命周期。

2. 成本

shared_ptr 通常有两个指针大小：一个指向对象，一个指向控制块。

控制块是动态分配的，里面通常有：

  • 强引用计数（多少个 shared_ptr）；
  • 弱引用计数（多少个 weak_ptr，不决定生命周期）；
  • 自定义删除器的副本；
  • 自定义分配器的副本；
  • 销毁对象所需的虚函数机制。

引用计数的增减必须是原子的，因为不同线程可能同时拷贝/销毁指向同一对象的 shared_ptr。原子操作通常比普通操作慢。
移动 shared_ptr 不改变引用计数：源被置空，目标接管，计数不变。所以移动比拷贝快。

3. 控制块的创建规则

控制块由“第一个创建 shared_ptr 的人”建立。规则：

  • std::make_shared 总是创建控制块（它新建对象，不可能已有控制块）。
  • 从 std::unique_ptr（或 std::auto_ptr）构造 shared_ptr 时创建控制块。
  • 从裸指针构造 shared_ptr 时创建控制块。
  • 从另一个 shared_ptr 或 weak_ptr 构造时不创建新控制块，而是共享已有的。

最后一条很重要：拷贝 shared_ptr 不会产生新控制块。

4. 同一个裸指针不能构造两个 shared_ptr

*pw 现在有两个控制块、两个引用计数；两个计数最终都会归零，于是 *pw 会被销毁两次，第二次就是未定义行为。

两个建议：

  1. 尽量不要把裸指针传给 shared_ptr 构造函数；优先用 make_shared。

6. shared_ptr 不支持数组

shared_ptr 的 API 只针对单个对象，没有 shared_ptr<T[]>。

有人会用 shared_ptr<T> 加一个执行 delete[] 的自定义删除器来指向数组。这能编译，但很糟：

  • 没有 operator[]，索引要靠指针运算，很难看。
  • shared_ptr 支持派生类到基类的指针转换，这对单个对象合理，对数组会破坏类型系统（unique_ptr<T[]> 明确禁止这种转换）。
  • C++11 已经有 std::array、std::vector、std::string，用智能指针指向“哑数组”通常说明设计有问题。

7. 记住

  • std::shared_ptr 用引用计数管理共享生命周期，方便但有控制块和原子计数成本。
  • 比 unique_ptr 通常大两倍，还要动态分配控制块。
  • 自定义删除器的类型不影响 shared_ptr 的类型，删除器存在控制块里。
  • 不要用同一个裸指针构造多个 shared_ptr，否则会重复销毁。
  • 需要从 this 创建 shared_ptr 时，用 enable_shared_from_this 和 shared_from_this()。
  • shared_ptr 不适合管理数组；用 std::array、std::vector 或 std::string。
