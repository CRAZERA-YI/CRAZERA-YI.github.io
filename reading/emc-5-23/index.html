条款23：理解 std::move 和 std::forward

std::move 无条件把参数转成右值，std::forward 只在参数原本绑定到右值时才转。

1. 它们不移动、不转发

std::move 不移动任何东西，std::forward 也不转发任何东西。运行期不生成任何代码,只是一个名字而已,和他们的功能没关系。

它们只是函数模板，做的事情是类型转换：

  • std::move：无条件转成右值。
  • std::forward：有条件转成右值。

2. std::move 的实现

一个接近标准的 C++11 实现：

std::move 接收一个万能引用，返回同一个对象的右值引用。

为什么要 remove_reference？因为如果 T 本身是左值引用，T&& 会折叠成左值引用；去掉引用后再加 &&，才能保证返回的真的是右值引用。

所以 std::move 只做一件事：把参数转成右值。它不保证这个对象一定能被移动，也不保证移动一定发生。

3. move 到 const 对象上会变成拷贝

text 是 const std::string。std::move(text) 的结果是 const std::string&&，也就是“const 右值”。

const std::string&& 不能绑定到 string&&，但可以绑定到 const string&，于是调用的是拷贝构造函数。

两个结论：

  • 想移动一个对象，就不要把它声明成 const；对 const 对象的移动请求会静默变成拷贝。
  • std::move 只保证结果是右值，不保证这个右值能被移动。

在 logAndProcess 内部，param 本身是左值（所有函数参数都是左值），直接传给 process 会调用左值重载。std::forward<T>(param) 的作用是：

  • 如果调用方传进来的是左值，就保持左值；
  • 如果调用方传进来的是右值，就转成右值。

所以 std::forward 是条件转换：只有实参原本绑定到右值时，才转成右值。

它怎么知道？信息编码在模板参数 T 里。左值实参让 T 推成 Widget&，右值实参让 T 推成 Widget。std::forward 根据 T 决定是否转换。具体机制见条款28。

不仅要写模板实参，还要保证传的是非引用类型；传错成 std::string&，就会变成拷贝。

更重要的是语义不同：

  • std::move 表示“无条件转成右值”，通常是在为移动做准备。
  • std::forward 表示“保持原来的值类别，转发给下一个函数”。

所以两者都应该保留，用在各自的场景。

6. 记住

  • std::move 执行无条件右值转换；它本身不移动任何东西。
  • std::forward 只在实参原本绑定到右值时，才转成右值。
  • 两者在运行期都不做任何事。
  • 想移动对象就不要声明成 const；对 const 对象的 std::move 会变成拷贝。
