读书笔记---Effective Modern C++(三)：条款11 优先用删除函数

条款11：优先用删除函数，而不是私有未定义函数

C++98 用“声明成 private 但不定义”来禁用函数，错误要等到链接期；C++11 的 = delete 直接在编译期把调用拦下来，而且任何函数都能删。
提一嘴,delete还能在移动构造的时候有点用,到时候再说

1. C++98 的做法：私有且不定义

标准库的 basic_ios 不允许拷贝，C++98 的写法是：

  • 声明为 private：外部调用者无权访问。
  • 不定义：如果成员函数或 friend 仍然调用它，链接时会因为找不到定义而失败。

问题是错误发现得太晚：编译能过，链接才报错。

2. C++11 的做法：= delete

被删除的函数在任何地方都不能用，包括成员函数和 friend。错误在编译期就出现，不用等到链接。

3. 为什么删除函数通常声明为 public

C++ 在检查“能不能调用”时，先看访问权限，再看是否被删除。如果删除函数是 private，有些编译器只会抱怨“这是 private”，而不告诉你“它已经被删除了”，错误信息更差。

所以惯例是：删除函数声明为 public。这样错误信息会直接说“调用了被删除的函数”。

private 只能用于成员函数；= delete 可以用于任何函数，包括非成员函数。

6. 记住

  • 优先用 = delete，不要再用 C++98 的“声明为 private 且不定义”。
  • 被删除的函数在编译期就不可用，错误比链接期更早、更清楚。
  • 任何函数都可以删除，包括非成员函数和模板特化。
  • 被删除的函数仍然参与重载决议，所以可以用它精确拦截某些类型。
