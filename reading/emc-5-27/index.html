条款27：熟悉万能引用重载的替代方案

条款26讲了为什么不能直接拿万能引用去重载。那如果既想要完美转发的效率，又需要区分不同参数类型（或者在构造函数里用完美转发），该怎么办？本条款给出五种替代方案。

1. 方案一：放弃重载

最直接的办法就是把不同功能的重载拆成不同名字的函数。比如把 logAndAdd 拆成 logAndAddName 和 logAndAddNameIdx。

缺点也很明显：构造函数名字固定，没法改名，所以这招对构造函数没用。

2. 方案二：退回传 const T&

回到 C++98 的写法，用 void logAndAdd(const std::string& name) 代替万能引用。

没有万能引用，就不会抢 int 重载。代价是放弃了移动语义和原地构造的高效，但在很多非性能瓶颈的地方，为了代码简单省心，这点性能损失完全可以接受。

3. 方案三：按值传递

5. 方案五：用 std::enable_if 约束模板

标签分发对普通函数很好用，但解决不了完美转发构造函数和编译器生成的拷贝/移动构造函数冲突的问题——因为编译器生成的拷贝构造函数不会走你的标签分发逻辑。

这时候必须动用 std::enable_if（SFINAE），在特定条件下直接把模板构造函数“禁用”掉。

我们需要在以下两种情况下禁用 Person(T&&) 模板构造函数：

  1. 实参类型是 Person 或 Person 的派生类：应该走拷贝或移动构造函数。注意不能用 std::is_same<Person, ...>，而要用 std::is_base_of<Person, std::decay_t<T>>，这样才能把派生类 SpecialPerson 也排除掉；同时要用 std::decay_t<T> 脱掉引用和 const/volatile 限定。

6. 完美转发的权衡与 static_assert

前三种方案（放弃重载、传 const T&、传值）在函数签名上写死了参数类型，简单直接；后两种方案（标签分发、std::enable_if）用了完美转发，效率最高，但也有两个缺点：

  1. 有些合法实参无法被完美转发。
  2. 报错信息极其难读。如果调用方传错了类型（比如传了 char16_t 字符串 Person p(u"Konrad Zuse");），错误会在转发链最底层的 std::string 构造处才爆出来，动辄一百多行模板报错。

7. 记住

  • 不使用万能引用重载的替代方案包括：使用不同的函数名、传 const 左值引用、按值传参、使用标签分发。
  • 通过 std::enable_if 约束模板，可以把万能引用和重载结合起来，由程序员精确控制编译器在什么条件下允许调用万能引用重载。
  • 万能引用参数通常有更高的性能，但在易用性和报错可读性上往往处于劣势。
