读书笔记---Effective Modern C++(一)：条款4 学会查看推导类型

条款4：学会查看推导类型

这篇就提到了,之前几篇文章说到的查看类型的函数了,其实不是很好用,而且我感觉也没啥用.那些查类型的技巧,我觉得也没啥用,看个乐呵

1. 编辑时：IDE

IDE 的代码编辑器通常会在鼠标悬停时显示变量、参数、函数的类型：

前提是代码基本处于可编译状态。IDE 能显示类型，是因为它内部跑着一个编译器（至少是编译器前端）；代码连解析都过不了，它也就推不出类型。

简单类型像 int，IDE 的信息一般够用。但遇到复杂类型，IDE 可能显示出一堆实现细节，反而不如不看。

3. 运行时：typeid

运行时打印类型，最直接的是 typeid,要使用这玩意得包含这个头文件#include <typeinfo>,其实这玩意不准啊,但是他是标准库的：

typeid 返回 std::type_info 对象，name() 给出一个 C 风格字符串。标准不保证这个字符串“好看”，但各家实现通常尽量帮忙：

  • GCC/Clang 输出 mangled 名：i 表示 int，PKi 表示 pointer to const int。可以用 c++filt 解码。
  • MSVC 输出比较直白：int、int const *。

看起来 T 和 param 是同一个类型。但 param 的声明是 const T&，T 是 const Widget*，所以 param 的真实类型应该是 const Widget* const&，和 T 不一样。

为什么错？因为 std::type_info::name 的标准要求把类型当成“按值传给模板”来处理。按条款1 的规则，引用会被剥掉；剥掉引用后如果还有顶层 const，也会被剥掉。于是 param 的 const Widget* const& 先变成 const Widget* const，再变成 const Widget*，最后和 T 显示成一样。

所以：typeid 可以用来粗略看类型，但不要拿它验证引用和顶层 const。

5. 记住

  • 推导出的类型可以用 IDE、编译器错误信息、Boost.TypeIndex 等工具查看。
  • 有些工具的结果可能既不好读也不准确，所以理解 C++ 的类型推导规则仍然是必要的。
