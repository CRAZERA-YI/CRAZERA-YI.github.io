读书笔记---Effective Modern C++(三)：条款16 const 成员函数要线程安全

条款16：让 const 成员函数做到线程安全

const 成员函数不代表“只读”，它可能通过 mutable 成员修改缓存；多个线程同时调用同一个对象的 const 成员函数时，也可能产生数据竞争。其实这节有点没啥必要了,这明明是所有函数都存在的问题,还专门提一个const函数,感觉其实有点莫名其妙

1. 一个看似只读的 const 函数

多项式求根很耗时，通常会把结果缓存起来：

单线程没问题。多线程就危险了：

两个线程都调用 const 成员函数，看起来都是读操作，不需要同步。但 roots() 内部可能同时读写 rootsAreValid 和 rootVals，这就是数据竞争，行为未定义。

问题不在 const 声明：从概念上说，求根确实不改变多项式。问题在于函数不是线程安全的。

5. 记住

  • const 成员函数也可能通过 mutable 成员修改状态，因此可能不是线程安全的。
  • 多个线程同时调用同一个对象的 const 成员函数，如果有内部写入，就是数据竞争。
  • 用 std::mutex 保护共享状态；mutex 需要声明为 mutable。
  • 单个变量/内存位置可以用 std::atomic；多个变量需要作为整体操作时，用 mutex。
  • mutex 和 atomic 都不可拷贝、不可移动，会让所在类也既不能拷贝也不能移动。
