读书笔记---Effective Modern C++(四)：条款21 优先用 make 函数

条款21：优先用 std::make_unique 和 std::make_shared

make 函数让你少写一遍类型、避免异常安全问题，make_shared 还能把对象和控制块放在一次内存分配里。只有在需要自定义删除器、花括号初始化、类专属 operator new 或大对象 + 长寿命 weak_ptr 时，才考虑直接 new。

1. make_unique 和 make_shared 的来历

std::make_shared 是 C++11 的一部分；std::make_unique 到 C++14 才进入标准库。

C++11 里可以自己写一个基础版：

它把参数完美转发给构造函数，用 new 创建对象，再交给 unique_ptr。这个基础版不支持数组和自定义删除器；标准库的 make_unique 支持数组，但也不支持自定义删除器。

注意：不要把自己的版本放进 namespace std，否则升级到 C++14 标准库时可能冲突。

make 函数一共有三个：std::make_unique、std::make_shared、std::allocate_shared。allocate_shared 和 make_shared 一样，只是第一个参数是分配器。

2. 好处一：不用重复写类型

用 new 的版本要写两遍类型。重复不仅多打字，还容易改了一处忘了另一处，最终导致类型不一致。

5.3 类有自定义 operator new/delete

有些类重载了 operator new/operator delete，通常只处理“正好 sizeof(Widget) 大小”的内存。

make_shared 申请的是“对象 + 控制块”的大小，不是对象本身的大小，和这类自定义分配器不匹配。所以对这类类，通常不该用 make_shared。

5.4 大对象 + 长寿命 weak_ptr

make_shared 把对象和控制块放在同一块内存里。对象销毁后，只要还有 weak_ptr 指向控制块，这块内存就不能释放。

如果对象很大，而 weak_ptr 在最后一个 shared_ptr 销毁后还活了很久，就会出现“对象已经销毁，但内存迟迟不释放”的情况。

直接 new 则可以把对象内存和控制块分开：最后一个 shared_ptr 销毁时，对象内存立即释放，只留下控制块等 weak_ptr。

7. 记住

  • 和直接 new 相比，make 函数避免重复类型、提高异常安全性；make_shared/allocate_shared 还能生成更小更快的代码。
  • 需要自定义删除器、需要花括号初始化时，不适合用 make 函数。
  • 对 shared_ptr，类有自定义内存管理、或者大对象 + 长寿命 weak_ptr 时，也要谨慎使用 make_shared。
  • 不得不用 new 时，把 new 和智能指针构造放在独立语句里，避免求值顺序导致的泄漏。
