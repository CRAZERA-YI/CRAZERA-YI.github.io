读书笔记---Effective Modern C++(一)：条款1 理解模板类型推导

条款1：理解模板类型推导

一句话：模板类型推导不是“把实参类型直接当成 T”，而是拿实参类型去匹配 ParamType 的形状。形状不同，结果差很多。

2. 三种情形

ParamType 的形态决定了用哪套规则，一共三种：

  1. ParamType 是指针或引用，但不是万能引用；
  2. ParamType 是万能引用（T&&）；
  3. ParamType 既不是指针也不是引用（按值传递）。

情形1：指针或引用，但不是万能引用

规则只有两步：

  1. 如果 expr 的类型是引用，先把引用部分丢掉；
  2. 用剩下的类型去匹配 ParamType，确定 T。

先看 T&：

要点：

  • cx 和 rx 的 const 会被保留，T 推成 const int，param 是 const int&。所以把 const 对象传给 T& 模板是安全的：调用方拿到的仍然是“不能改”的引用。
  • rx 虽然是引用，但推导时引用被忽略，T 不是 const int&，而是 const int。
  • 对非万能的右值引用参数（比如 void f(std::vector<T>&&)），推导逻辑和左值引用一样，只是只能绑定右值。
  • 加入在左值引用里面传入右值,编译器会直接报错

因为 param 本身已经是 reference-to-const，const 不需要再被推导进 T。这是很多人第一次会猜错的地方。

指针 T* 同理：

指针指向对象的 const 会保留；指针自身的顶层 const 在按值传递时会被忽略，见情形3。

情形2：万能引用

顾名思义,万能引用既可以传入左值也可以传入右值
T&& 只有在 T 需要推导时才是万能引用。像 void f(Widget&&)、std::vector<T>&& 这种都不是，它们只是普通的右值引用。

万能引用的规则：

  • 实参是 lvalue(左值)：T 和 ParamType 都推导为左值引用。这是模板推导里唯一会把 T 推成引用的情形，也是“声明像右值引用、推导结果却是左值引用”的情形。
  • 实参是 rvalue(右值)：按情形1的普通规则处理。

背后的机制是引用折叠：T 推成 int& 后，T&& 就变成 int& &&，折叠成 int&。完整推导在条款24，这里只要记住“左值特殊、右值普通”。

关键点：只有万能引用会区分左值和右值。普通的 T& 不区分，而且不能绑定右值；const T& 虽然也不区分，但可以绑定右值。

情形3：按值传递

规则：

  1. 和之前一样，expr 是引用就忽略引用；
  2. 忽略引用后，如果还带 const 或 volatile，也一并忽略。

为什么可以忽略 const：param 是一个独立的副本，cx 不能改，不代表副本不能改。

5. 记住

  • 引用实参推导时按非引用处理，引用被忽略。
  • 万能引用参数对左值特殊：T 和 param 都成为左值引用。
  • 按值参数忽略实参的顶层 const/volatile。
  • 数组名和函数名在按值推导时退化成指针；用引用接收时保留原类型。
  • 推导结果由 expr 的类型和 ParamType 的形式共同决定。
