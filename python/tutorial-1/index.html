1. 变量

= 不是“相等”，而是“把右边的值绑定给左边的名字”。变量可以随时改，Python 始终记录最新值——书里的这句话是整个动态类型体系的地基。

命名规则

规则 可行 不可行
只能含字母、数字、下划线 message_1 message-1
不能以数字开头 message_1 1_message
不能含空格 greeting_message greeting message
不能用关键字和内置函数名 message print、class
简短且有描述性 name_length length_of_persons_name
避开易混字符 count l、O（像 1 和 0）

最好用小写变量名,大写一般拿来命名类名

NameError：名字对不上

traceback 三要素：文件与行号、出错的那行代码、错误类型与描述。书里对 NameError 的解释很到位：通常只有两种原因——用了变量却没赋值，或者变量名拼错了。有意思的是，如果把两处都拼成 mesage，程序反而能正常运行：解释器不做拼写检查，只要求前后一致。

语法错误：引号嵌套

解释器把第一个单引号和撇号之间的内容当成字符串，后面的文本就“不是 Python 代码”了。改成双引号包裹即可。书里给了一个实用技巧：代码和被当成普通文本的部分颜色不一致，往往就是引号不匹配。

Python 2 的 print

现在应该没人用python2了,了解一下就行了

Python 3 里 print 是函数，括号是语法的一部分；Python 2 里它是语句。看到不带括号的 print，基本可以判断是 Python 2 代码。

整数与运算

** 表示乘方，运算优先级和数学一致，括号可以改变次序。书里强调空格不影响计算，只影响阅读——这种“运算符两侧留空格”的写法后来成了 PEP 8 的默认风格。

2.5 注释

# 之后的内容全部被解释器忽略。书里对“写什么”的判断标准很实用：如果你在找到这个方案之前考虑过多个方案，就写注释说明为什么选它。换句话说，注释解释决策，而不是复述代码。作者还提到一个现实理由：代码是多人协作的，注释是专业习惯，而删除多余注释比事后补注释容易得多。
